# Route 1: Build in VS Code and copy the app by hand

This is the simplest booth route. Start with an empty folder on the laptop,
ask Copilot to build one small badge app, then copy the finished app folder to
the badge in Windows File Explorer.

You do not need a GitHub repository, a team folder, or command-line tools for
this route.

## Before you start

- Use a Windows 11 laptop with VS Code, GitHub Copilot, and an internet
  connection.
- Use a data-capable USB cable and any adapter needed to connect the badge.
- Sign in to GitHub Copilot with your own account.
- Ask booth staff to confirm that Copilot can read `badge-app-builder` and
  its 2026 reference files. A skill in another repository is not automatically
  available in an empty app folder.
- Keep the badge connected only when you are ready to test or copy files.
- Do not update firmware during an app-building session.

A charge-only cable will power the badge but may not transfer files.

## 1. Make a local folder for the app

1. Open File Explorer with `Windows key + E`.
2. Create a folder in Documents named `Badge Projects`.
3. Inside it, create one folder for the app, for example `star-counter`.
4. Open VS Code.
5. Choose **File > Open Folder** and select the `star-counter` folder.

This folder is the whole app. Do not create a repository or clone a sample
project.

## 2. Ask Copilot to create the app

Open Copilot Chat in VS Code and select **Agent** so Copilot can create files.
Ask it to use `badge-app-builder`. Tell it that there is no repository and
that the open folder is the app folder. If it cannot find the skill or its
references, stop and ask booth staff to load them.

Example:

> Use the badge-app-builder skill. First read its 2026 hardware, app-contract,
> API, and physical-badge references. If they are missing, stop and tell me.
> I am at a booth with no repository. Build a small Universe 2026 MicroPython
> app directly in the open folder, not in TeamN or badge/apps. My app idea is:
> a counter that increases when I press SELECT. Create __init__.py, a real
> 24 x 24 icon.png, and any required assets. Use the 2026 runtime globals,
> logical BUTTON_* controls, a short non-blocking update(), and a module-level
> run(update) call. Leave HOME available to return to the menu. Use the skill's
> app-directory pattern for local modules and assets; do not use os.path or
> desktop Python packages. Do not clone a repo, change firmware, or add
> credentials. Distinguish the USB drive's apps folder from /system/apps in
> running code. Explain how to copy and test the app.

Replace the counter idea with your own small app idea.

Ask for a small first version. A simple screen and one button action are
easier to test at a booth than networking or sensor features.

## 3. Review the files before copying

In the VS Code Explorer, confirm that the app folder contains:

```text
star-counter
├── __init__.py
├── icon.png
└── assets
```

The `assets` folder is optional. If the app needs images or other files, keep
them inside this app folder and ask Copilot to use paths relative to the app.
The `icon.png` must be a real 24 x 24 PNG image, not an empty placeholder.
Use **View > Show > File name extensions** in File Explorer if you need to
check that the entry file is named `__init__.py`, not `__init__.py.txt`.

Ask Copilot to review the app against `badge-app-builder`:

- Use the 2026 `badge`, `screen`, `image`, `font`, `color`, and `shape` APIs,
  not the old 2025 drawing or `io` input APIs.
- Use logical SELECT, BACK, and direction controls, not physical A/B/C names.
  HOME must still return to the menu.
- Start the app with `run(update)` outside an `if __name__` check.
- Keep assets inside the app folder and use the skill's app-directory pattern
  without `os.path`. The normal drawing area is 160 x 120; use
  `screen.width` and `screen.height` when laying out the screen.

If Python 3.10 or newer and the skill's bundled `validate_app.py` are available,
ask Copilot to run that file using its actual installed path and the full path
to your app folder. The validator accepts a standalone app folder; a TeamN
folder or repository is not required. Fix errors and review warnings.
If Python or the checker is missing, ask for a file review instead.
Do not run an invented command. A file check does not replace a physical test.

## 4. Copy the app to the badge

1. Close any serial monitor, REPL, or other program that is connected to the
   badge.
2. Connect the badge with the data-capable USB cable.
3. Double-tap the badge's RESET button. Wait for its USB Disk Mode screen.
4. In File Explorer, open **This PC** and open the new badge drive.
5. Open the `apps` folder at the root of the badge drive: `BADGER\apps`.
   Windows also assigns the drive a letter.
6. Copy the `star-counter` folder itself from Documents.
7. Paste it into `BADGER\apps`.

Choose an app name that is not already on the badge. Do not overwrite or
delete an existing app; ask booth staff if the name is already in use.

The result should look like this:

```text
BADGER
└── apps
    └── star-counter
        ├── __init__.py
        ├── icon.png
        └── assets
```

Do not copy the whole `Badge Projects` folder, a ZIP file, or a `.uf2` file.
The `RP2350` drive is for a deliberate firmware update, not for installing an
app.

On the 2026 firmware tested here, `apps` on the USB drive appears as
`/system/apps` inside the running badge. These are two views of the same
folder. Do not create a `system` folder on the USB drive to match a code path.

Badge firmware can change the drive name or folder layout. If you do not see
the root `apps` folder, stop and ask booth staff to check the firmware and
existing app location. Other firmware may expose `system\apps` or use a drive
name such as `TUFTY`. Do not guess from the name or create a new folder.

## 5. Eject and test

1. In Windows, use **Safely Remove Hardware and Eject Media** in the taskbar,
   or right-click the badge drive in File Explorer and choose **Eject**.
2. Wait for Windows to say the device is safe to remove or for the drive to
   disappear.
3. Press RESET once if the badge does not return to its launcher.
4. Open the new app from the badge menu.
5. Try each screen and button. If the app saves data, exit and reopen it to
   check that the data is still there.
6. Press HOME and confirm that the badge menu returns.
7. If the app saves data, press RESET once, reopen the app, and confirm that
   the data is still there.

To install a corrected version, first copy the old app folder from the badge
to a backup folder on the laptop. Then replace only your app folder with the
complete corrected version. Do not change the menu, `main.py`, shared assets,
or other system files.

## 6. If the app shows an error

Take a clear photo of the entire error, including the file name and line
number. Give that error to Copilot and ask it to check the exact API and all
places where the same API is used. Fix related calls together, then copy the
app again and retest.

Do not assume every badge has the same firmware just because it has the same
case. If you are unsure which firmware it uses, ask booth staff for help.
A serial connection can stop or reset the running app. Wait until any serial
command finishes before testing a button or movement.

## Physical test rules for any badge app

- Check the actual badge API before changing code. A method that seems
  reasonable may not exist on the installed firmware.
- Check every use of a failing call, not only the first line in the error.
- Test that one button press cannot trigger two actions across screens.
- Motion thresholds are not universal. Test sensor behavior on the actual
  badge instead of copying another app's values.
- A successful simulator or file-copy step does not prove that the physical
  badge works. Open and test the app on the badge.
