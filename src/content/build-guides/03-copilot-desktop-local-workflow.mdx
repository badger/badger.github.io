# Route 3: Build in the GitHub Copilot desktop app

Use this route if you want to work with Copilot in its separate desktop app
instead of in VS Code. Copilot edits a local folder on the laptop. You then
copy that app folder to the badge with Windows File Explorer.

You do not need a GitHub repository. You do need a local folder and Git for
Windows installed, as required by the Copilot app.

## Before you start

Use a signed-in GitHub Copilot account, an internet connection, and a
data-capable USB cable. Ask booth staff to confirm that the desktop app can
read `badge-app-builder` and its 2026 reference files. A skill installed only
in another repository is not automatically available in this local folder.
Do not update firmware during an app-building session.

Booth staff: install the complete `badge-app-builder` folder as a personal
skill, including `SKILL.md`, `references`, and `scripts`, outside the attendee's
app folder. Use the local skills link below for installation locations, then
confirm the desktop session can read the skill before starting.

## 1. Make a local folder

1. In File Explorer, create `Documents\Badge Projects\my-app`.
2. Open the GitHub Copilot app and sign in.
3. Under **Projects**, choose **Add project > Local folder or repository**.
4. Select the `my-app` folder on the laptop.
5. Start an **Interactive** session for this local project.

If Git for Windows is not installed, ask booth staff for help or use the
VS Code route. You do not need to create or publish a repository just to save
the app files in this local folder.

Choose a local session, not a cloud session. A cloud session runs on another
computer and cannot see the badge connected to this laptop. If the Copilot
app creates a separate local work folder, note where it is saving changes.

## 2. Ask Copilot to build the app

Tell Copilot to use the `badge-app-builder` skill installed for the booth.
Tell it to make a complete app in the open local folder, without expecting a
repository or pre-existing project files. If the skill or its references are
missing, stop and ask booth staff to load them.

Example:

> Use the badge-app-builder skill. First read its 2026 hardware, app-contract,
> API, and physical-badge references. If they are missing, stop and tell me.
> I am at a booth with no repository. My app idea is: a counter that increases
> when I press SELECT. Build a Universe 2026 MicroPython app directly in this
> local folder, not in TeamN or badge/apps. Create __init__.py, a real 24 x 24
> icon.png, and any required assets. Use the 2026 runtime globals, logical
> BUTTON_* controls, a short non-blocking update(), and a module-level
> run(update) call. Leave HOME available to return to the menu. Use the skill's
> app-directory pattern without os.path or desktop Python packages. Do not
> clone a repo, add credentials, change firmware, or assume you can reach the
> physical badge yet. Distinguish the USB drive's apps folder from /system/apps
> in running code. Tell me the full folder path where you saved the app and
> how to test it.

Replace the counter idea with your own small app idea.

Review every changed file in the app's **Changes** view before keeping it.
Confirm that the app source and all required assets are saved under the local
`my-app` folder.

## 3. Check the app

Ask Copilot to review the entry file, the real 24 x 24 PNG icon, and all assets
using `badge-app-builder`. The app must use the 2026 drawing and input APIs,
not the archived 2025 APIs. Its `run(update)` call must not be inside an
`if __name__` check. The normal drawing area is 160 x 120; use `screen.width`
and `screen.height` for layout.

If Python 3.10 or newer and the bundled `validate_app.py` are available, ask
Copilot to run the checker from its actual installed path with the full path
to your app folder. It supports standalone folders; a repository is not
required. Fix errors and review warnings. If Python or the checker is missing,
use a file review and physical testing instead. Do not run a made-up command
or clone a repository just for this check.

For a quick visual check, you can also paste `__init__.py` into the
[Badgeware Web Simulator](https://pimoroni.github.io/badgeware-web-simulator/)
and add its local modules and assets at the same relative paths. Read the
skill's emulator reference first. Choose **Run** or **F5**, then click the 3D
badge to focus its controls.

The simulator models upstream Tufty 2350, not the full custom 2026 badge.
It may lack 2026 logical controls or hardware APIs. Do not change the app to
the old A/B/C input API or add fake hardware behavior to make a preview run.
Use the real badge for those checks. A preview cannot prove physical sensors,
wireless, IR, battery, or exact timing.

## 4. Install the app from the local folder

1. Close other programs that may be using the badge's serial port.
2. Connect the badge with a data-capable USB cable.
3. Double-tap RESET and wait for USB Disk Mode.
4. In File Explorer, open the badge drive, then its root `apps` folder:
   `BADGER\apps`.
5. Copy the `my-app` folder from the Copilot app's local workspace into that
   `apps` folder. Confirm that
   `BADGER\apps\my-app\__init__.py` exists. Use an app name that is
   not already on the badge. Do not overwrite or delete an existing app;
   ask booth staff if the name is already in use.
6. Safely eject the badge drive in Windows and wait for its confirmation.
7. Press RESET once if needed, open the app from the badge menu, and test it.
   Try every screen and control, confirm HOME returns to the menu, and reopen
   the app to check any saved data. If it saves data, also press RESET once
   and reopen the app to check that the data is still there.

If Copilot's local sandbox will not let the agent access the badge drive,
copy the folder yourself in File Explorer. Do not turn off broad safety
settings just to copy one app.

On the tested 2026 firmware, `apps` on the USB drive appears as
`/system/apps` inside the running badge. Do not create a `system` folder on
the USB drive to match that code path.

If the root `apps` folder is missing, stop and ask booth staff to check the
firmware and existing app location. Other firmware may expose `system\apps`
or use a drive name such as `TUFTY`. Do not guess from the drive name or create
a new folder. Do not copy app files to the `RP2350` firmware-update drive.

For a corrected version, first back up the installed app folder to the laptop.
Then replace only your app folder with the complete corrected version. Do not
change the menu, `main.py`, shared assets, or other system files.

## 5. When something fails

Photograph or copy the full error, including the file name and line number.
Ask Copilot to verify the API for the badge's actual firmware and inspect
every place the failing call is used. Do not assume a method exists because
it works on a different badge or in the simulator.

Serial connections can reset or interrupt the running app. Use one serial
program at a time, and wait until it is finished before asking someone to
test a movement or button.

## Test status: October 13, 2026

The shared physical-install steps passed on a Mac with a Badger MicroPython
1.29.0-preview build dated October 9, 2026. A new app copied to `BADGER/apps`
opened from the menu, loaded a local module and PNG image, and responded to
SELECT, RIGHT, BACK, and HOME. Its saved count survived HOME and RESET.
Existing app and system files were unchanged; no firmware update was performed.

Still needs a Windows check:

- Git for Windows, Copilot desktop installation, and sign-in.
- Adding a standalone local folder, loading the personal skill, starting an
  Interactive session, reviewing Changes, and finding the actual saved files.
- File Explorer drive name and letter, whole-folder copying, safe eject,
  and backup and replacement of an existing app.
- Any optional simulator preview. The browser steps were not exercised here.

This verifies the shared badge behavior, not the Copilot desktop workflow.
