# Build with the GitHub Copilot App

Describe your idea in the GitHub Copilot desktop app. Copilot builds the
app and copies it to your connected badge. You test it on the badge.

The Windows PC already has `hyb26-skill`, a set of instructions and tools
that helps Copilot build apps for this badge. Use the **GitHub Copilot**
app, not Microsoft Copilot. You do not need to install the skill or write
code yourself.

## 1. Connect the badge for the Copilot App

1. Connect the badge to the PC with a USB cable that transfers data.
2. Quickly press the badge's **RESET** button twice. Wait for **USB Disk Mode**.
3. Press **Windows key + E** to open File Explorer. Select **This PC** and
   find the **BADGER** drive. Windows adds a drive letter; yours may differ
   from someone else's.
4. Leave the badge connected in Disk Mode while Copilot works.

If BADGER does not appear, ask event staff for help. If you see **RP2350**,
stop: that drive is for firmware updates, not apps. Do not copy files to it
or change the firmware.

## 2. Open a local project in the Copilot App

1. Open the **GitHub Copilot App**.
2. Under **Projects**, select the **Badge Projects** folder prepared by staff.
3. Start an **Interactive** session for that local project.

Use a local session on this PC, not a cloud session. A cloud session cannot
access the badge plugged into this PC. Use the project session, not a
general chat, so Copilot has a place to save your app.

If the project is missing, use the add control next to **Projects**, choose
**Local folder or repository**, and select **Badge Projects** in Documents.
If the folder does not exist, create it in File Explorer first. You do not
need to create or clone a repository. If the app reports a missing tool,
ask staff to check the PC setup.

## 3. Give the Copilot App your idea

Tell Copilot what you want to make in the **local project session** and ask
it to use `hyb26-skill`. The prompt below is only an example. You do not need
to copy it or use it as written; describe your own idea in your own words.

<CopyPrompt prompt="Use hyb26-skill to make a badge app with a counter that increases when I press SELECT. Walk me through anything I need to do with the badge using plain English." />

Answer Copilot's questions. If a permission request appears, check that it
is for your local project, the installed skill tools, or BADGER before
allowing it. You may still need to approve a tool action; the prompt does
not bypass those controls.

Copilot should check the app before copying it. If the skill or Python is
missing, or Copilot cannot identify the badge, ask staff for help rather
than skip the checks.

## 4. Test the Copilot App's result on your badge

Wait until Copilot says copying has finished. Follow its test steps:

1. In File Explorer, right-click **BADGER** and choose **Eject**. Wait until
   Windows confirms it is safe to remove or the drive disappears.
2. Press **RESET** once. Open your app from the badge menu.
3. Try its screens and buttons, then press **HOME** to return to the menu.
   If the app saves data, reopen it and check the data after a reset too.

Copilot can check files and copy them, but it needs you to report what the
badge displays and how the controls work. Sensors and wireless features
need tests on the real badge; passing file checks does not prove they work.

## 5. Continue in the Copilot App

Tell Copilot what you want to change. If the badge shows an error, type
the error message into Copilot, including any file name and line number
shown. Describe what you were doing when it happened and ask Copilot to
try to fix it. If anything is unclear, ask a volunteer for help.

Before copying a fix, reconnect the badge if needed and press **RESET**
twice to return to Disk Mode. Follow Copilot's steps to copy and test the
updated app.

When updating your own app, tell Copilot it is an update so it uses the
skill's replacement option and keeps a backup. Do not replace someone
else's app or change shared badge files.

If Copilot cannot access BADGER, ask it for the full path to your checked
app folder and the correct destination. You can copy that one folder in
File Explorer as a fallback, then eject and test as above. Do not disable
broad safety settings to give access.
