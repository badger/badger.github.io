# Browser simulator

The `/simulator` page uses CodeMirror for editing and a locally hosted MicroPython WASM worker for simulation. It loads the saved project on startup and runs it automatically. With Auto-run enabled, source changes restart the simulation after a 650 ms pause in typing. Stop disables automatic simulation; Run, F5, or Command/Ctrl+Enter runs the current project manually.

Projects contain an `__init__.py` entry point, companion Python and text files, and binary assets. The file sidebar lets users switch between files, edit text, preview images, and add files. Each simulation stages the complete project in the virtual filesystem, sets its working directory and import path, and executes the entry point using its actual filename. A fresh worker terminates the previous program and resets its virtual state. The display receives RGBA framebuffer messages. Pointer and keyboard controls release held buttons when focus changes, and execution pauses in hidden tabs.

The Apps collection uses the same installable-app selection rules as `/apps`. `public/editor-apps/catalog.json` records the bundled public `badger/home` revision and lists every project file. Run `npm run sync:editor-apps` to refresh these apps, including modules and assets. The sync also bundles the `menu` launcher as the catalog's `launcher` entry; it is not listed as an editable app.

## About page simulator

On wide screens, the working badge sits beside the hardware specifications. Narrow screens put the badge first. `src/lib/badge-controls.ts` supplies the approved control names and SVG icons to both the About page buttons and `badge-control-symbols.astro`. The shared 3D view draws these same SVGs beside the five physical buttons and the existing Home touchpad; clicking a symbol uses its existing input bit. Both model hosts include the SVG source component, so the editor's 3D model gets the same markings without changing its separate page controls. No case-model rebuild is required.

`/about-badge/` boots the Mona OS 4.0 menu in the same worker and renders it on the editor's 3D badge model (`initBadgeModel`). Zooming moves the orbit target toward the badge screen as the camera closes in, and back to the model centre when zoomed out. `npm run sync:editor-apps` bundles the menu from `badger/home` `badge/apps/menu` as the catalog `launcher`. Each device `.mpy` module is replaced by its `src/<module>.py` source, because the simulator cannot load `.mpy` files. `launcher.stock` lists the stock apps, taken from the menu's `anim/<app>.bin` icons. The page stages only the menu at `/system/apps/menu` and the stock apps at `/system/apps/<name>`. `src/lib/badge-firmware-compat.ts` registers stand-ins for firmware-frozen modules that are missing from the vendored runtime (`aye_arr` and `badgeware.ir`) in `sys.modules`. `public/simulator/filesystem/sparkle.py` replaces the firmware's Sparkle supervisor: `request_local_show()` wraps the next `run` call to draw the local show's bouncing Invertocat and case lights, with the Bluetooth mesh shimmed out. Three SELECT presses or the 10-minute timeout end the show and call `machine.reset()`. It also patches newer firmware APIs: `display.set_async`, `machine.reset_cause`, and the three-argument `missing_details.show`. Both this page and editor simulations use it; no extra files are staged. IR does nothing in the simulator. A Python launcher in `src/lib/badge-os-simulator.ts` replicates `badge/main.py`: it runs the menu, launches the selected app, and returns to the menu when HOME is pressed or the app calls `reset()` or fails. This loop is needed because `machine.reset()` and pin IRQs are inert in the simulator. The page shows the badge photo until the 3D model has loaded and the first frame renders. If the browser lacks module workers, WebAssembly, WebGL, or `ImageData`, or the simulator or model errors or times out, the worker stops and the photo remains.
The Examples collection includes all 36 examples from the simulator's categorized manifest at revision `eb3b3fbf27e6e61635aef5de11ab17e6303e8c20`. `public/editor-examples/` includes their original source, manifest categories and descriptions, required images and fonts, and MIT notice. Run `npm run sync:editor-examples` to restore them from that pinned revision. Update `simulatorRevision` in `scripts/editor-example-source.mjs` only when updating the bundled runtime and its provenance notices together. Opening an example creates an editable `example-<name>` app with an `__init__.py` entry point. References to bundled `/system/assets/` files become app-local asset paths, so first installs include those dependencies and avoid collisions with existing badge app names.

Apps, Examples, and On your badge share a searchable card picker. Cards show complete titles and descriptions; Examples retain their upstream categories. Preview runs the selected card in a separate worker without replacing the editor project. Only one card preview runs at once, and opening the picker pauses the main simulation. Changing the collection or search, closing the picker, or leaving the page terminates the preview. Edit opens the complete project and uses the existing draft replacement guard. Installed badge apps are read fresh when opened.

The current project, including edited files and assets, is saved in the `badger-editor-projects` IndexedDB database. Replacing an edited project with New app, an example, a local file, or a badge app requires confirmation. The guard includes renamed projects and empty added files and survives draft restoration. Earlier drafts without a checkpoint are protected conservatively. Earlier single-file localStorage drafts are migrated when no project draft exists. Open and Download icon buttons load a local Python file and save the active file. Undo and Redo use the active text file’s CodeMirror history, which is retained when switching files within the project.

On screens at least 1024 pixels wide, drag the divider between the code and simulator panes to resize them. Arrow keys adjust the split, Shift uses larger steps, and double-click or Enter restores the default. The split is saved locally. Narrow screens keep the stacked layout. Drag the bottom handle to resize both panes vertically on any screen size. Up/Down keys adjust the height; double-click or Enter restores 620 pixels. Height is saved separately from the horizontal split. The source editor fills the available height, while simulator contents scroll when needed.

The toolbar's Full screen button expands the entire workspace. Native browser fullscreen is used when available, with a viewport-filling fallback when unsupported or denied. Upload controls, the picker, replacement confirmation, and horizontal resizing remain available. Pane heights fill the remaining screen space, with a stacked layout on narrow screens. The bottom height handle is hidden until exiting, and the saved normal height is preserved. Exit full screen or Escape restores the page; Escape first dismisses an open dialog.

## Badge disk workflow

Connect the badge over USB and double tap its reset button to enter disk mode. Connect badge opens the native directory picker. Select the BADGER volume itself; it must contain an existing `apps` directory. This requires HTTPS or localhost and a browser supporting `showDirectoryPicker`, such as Arc.

The connected badge app selector reads Python apps from `/apps`. Opening an app loads its source, companion files, and assets for editing and simulation. Hidden files and Python caches are skipped. Menu and Startup are protected. Projects are limited to 16 MB and twelve path components.

The badge mounts the USB volume at `/system` during execution. Simulation therefore stages each project only at `/system/apps/<name>`, corresponding to `/apps/<name>` on the selected volume. It does not create aliases under the original example name. Apps referencing their original folder in Python source must retain their name or have those paths edited before simulation or upload. Companion modules are checked too.

Uploads to an existing app write only edited and added files from a badge app or example. Unmodified files and assets are skipped without opening or reading them. Restored drafts retain their verified-file baseline across reconnects. Only files actually verified are marked as known on the badge, so a partial example update does not claim its other files match the device. Edits to known files changed externally cause the upload to stop before those files are overwritten. Editing an unverified example file that differs from its installed version requires allowing the update explicitly. UTF-8 byte-order marks are preserved to prevent unchanged text files being rewritten.

The button shows the number of files eligible for upload, or No changes when there is nothing to send. A first install copies the entire project, including required modules and assets, and is labelled Install with the full file count. A new or locally opened project can also replace its files in an existing destination after confirmation. Other files in an existing app remain intact. The uploader writes companion files and assets before `__init__.py`, closes each writer, and verifies each file byte for byte. Progress shows the current filename and completed count. A failure restores files already written or removes a newly created app. Upload uses a snapshot so edits typed during a write remain in the editor afterward. The app selector updates from its cached list after upload; Refresh files performs an explicit disk rescan.

Uploads rewrite each changed file. The browser's `createWritable` API writes to a temporary file and replaces the original at close. Seeking to a changed line would still copy and replace the file, so byte-range patches do not provide an in-place USB update.

Disconnect drops the editor's directory handle. Eject BADGER through the computer before unplugging it, then restart the badge to run the uploaded project. Browser filesystem tests do not establish physical USB acceptance.

## Runtime provenance and limits

The runtime is adapted from badgeware-web-simulator commit `eb3b3fbf27e6e61635aef5de11ab17e6303e8c20`. Its MIT notice and the MicroPython MIT notice remain in `public/simulator/LICENSE`. `public/simulator/THIRD_PARTY.md` records the compiled-dependency audit, source revisions, artifact hashes, and notices in `public/simulator/licenses/`. The interface uses the Badger site theme and GitHub branding. The upstream interface, 3D model, OS apps, and promotional assets are excluded. The worker reports boot failures, Python failures, and completed programs to the editor. Runtime, font, module, and example requests use the site's origin.

The runtime provides a 320 by 240 color display and six keyboard or pointer buttons. Compatibility modules map the catalog's newer directional button names to these inputs, with distinct BACK and MENU actions. Touch and click work on the printed pads of the 3D model (white circle SELECT, beige circle BACK, D-pad, and pills MENU and HOME); pressed pads are highlighted. The +/− buttons zoom the model in 5% steps. `src/lib/badge-motion.ts` forwards browser `devicemotion` data to the worker as IMU readings, requesting permission on iOS after the first tap. Without motion data the badge reads as held upright. Wi-Fi, `network`, and `ntptime` report connected. `requests`, `urequests`, and `fetch` send HTTP through synchronous browser XHR, so responses are subject to CORS. Sockets are not available, so Camera and Copilot need the physical badge. Simulator secrets contain placeholder Wi-Fi values only; actual device credentials are never loaded. `bluetooth` is an inert stub, so Merge Conflict reaches its lobby and asks you to hold badges back to back. `powman.reset_into_msc` shows a USB Disk Mode screen that waits for RESET (Home in the simulator). The toolbar above the model has Screen (zoom to the display), Full (show the whole badge), and Rotate. Rotate turns the model 180° and sets the upside-down input bit (the editor's Upside down option), so the firmware autorotates the display, the IMU reads upside down, and the touch pad directions swap. Zoom follows the screen in either orientation. Physical sensors and networking require testing on the badge.

`public/simulator/filesystem/` is marked `-text` in `.gitattributes`. `filesystem.json` records byte sizes, so CRLF checkouts would truncate modules and stop the simulator from booting. Bundling an app does not establish complete runtime compatibility.

## Verification

Run `npm run test:editor` for project and upload tests, `npm run test:app-descriptions` for the existing catalog tests, and `npm run build` for the static site build. Editor tests use an in-memory disk adapter and cover catalog assets, nested project reads, virtual filesystem staging, complete uploads, dirty-file updates, external modifications, rollback, failed-write cleanup, protected apps, unsafe paths, and denied disk access. Browser and physical badge testing remain separate acceptance checks.
